# Organizer event management layout

All events / Your events now uses a consistent event card with a colored header, venue/time/status and a short facts row for confirmed capacity, price and teams. Event details/equipment are collapsed by default. Manage players is the primary action; drafts retain a visible Publish event control. Event actions groups edit, complete, cancel and delete according to the same role/status permissions as before. Cancel/delete confirmations and busy states remain in place. The create/edit form and backend behavior are unchanged.

Each event contains its management area rather than placing it below the card. Only one event opens at a time. Players, Teams and History buttons reveal one section at a time. History and team data are fetched when their view is opened; the first view opens the roster without also expanding the team board or audit trail.

Players defaults to active confirmed/waitlisted seats. Summary counts include all seats, including guests and cancelled attempts. The status filter exposes confirmed, waitlisted, cancelled and all bookings, with name/nickname/account search that also finds guests through the booking account. Cancelled histories are retained. Each compact row shows player/account identity, self/admin ratings for account holders, team assignment, booking status, payment summary and recorded-strike/late-cancellation flags. Manage opens one seat at a time for contact information, booking date, payment reviews, attendance, strike dialogs and the existing note/confirmation-based party removal or queue override. Payment and strike dialogs retain their existing components and behavior. Changes refresh both the roster and event summary counts.

Teams keeps manual assignments, self/admin rating display, auto-balance and reshuffle actions. Team settings and explanatory copy are collapsed by default. History retains action, actor, time and reason/note information with an independent loading state and refresh action.

The layout uses existing theme variables throughout, responsive rows and semantic headings, labeled filters, native disclosure controls, and expanded/pressed states on management controls. Backend authorization, reviewed-strike eligibility, payment rules and team balancing logic are unchanged.

Validation: production Angular build, strict frontend harness type checking and all 17 profile/frontend logic tests passed. Added checks cover active/cancelled visibility, searching guests by booking account, retaining one expanded player, distinguishing payment review states and loading history on demand without accepting stale event responses. Browser tools and their DOM dependencies are not installed here, so visual, mobile, keyboard and modal interaction review remains manual.
