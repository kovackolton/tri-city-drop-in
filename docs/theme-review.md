# Editable theme and header shortcuts

Edit `apps/web/src/theme.css` to change colors. The `:root` block defines light mode, and `:root[data-theme="dark"]` overrides dark mode. Tokens cover the page, surfaces, text, borders, accent/focus, primary controls, sidebar, game banners, notices, badges, dialogs, thumbnail placeholders, Google sign-in button and avatar palettes. Components use semantic variables/utilities rather than raw color values. Layout and shared control rules remain in `styles.css`; its `@theme inline` block maps semantic Tailwind utilities to the editable variables.

The palette is based on primary `#c02f2a` (red), secondary `#3c7cdb` (blue) and tertiary `#348062` (green). Brand source variables live at the top of `theme.css`. Light-mode primary controls/navigation use red, secondary outlined controls and links use blue, and game banners/success surfaces use green. Dark mode uses readable tints and deeper backgrounds from the same palette. The original blue is retained as a brand/border color; small blue text uses a darker variant on light surfaces. Colored sidebars/game banners have a separate light focus-ring color. Avatar identity colors and the Google-branded button remain separate.

Contrast checks measured 32 text/background pairs per theme at 4.5:1 or above (minimum 4.52:1 light and 6.80:1 dark), plus eight control/focus pairs per theme at 3:1 or above. Date-tile text was also checked against its composited translucent background. These are palette checks; browser review of rendered states remains manual.

The top-right sun/moon toggle is available while signed in or signed out. It follows the device theme initially, including device changes until an explicit choice is made. Clicking persists light/dark in browser localStorage under `tri-city-theme`, including across sign-out and reload. Other tabs synchronize changes. Blocked storage still allows toggling for the current session. There is no server-side preference or external service dependency. `public/theme-init.js` selects the theme before the application starts to avoid a bright initial frame for dark-mode users.

Signed-in profiles see a notification bell and a settings cog in the same header. The bell opens Notifications and displays the existing unread count (visually capped at 99+; the accessible label has the full count). The cog opens My profile. Existing sidebar navigation stays available. Icons are inline SVG and require no new package, image files or remote icon service. Controls have text accessibility labels, focus outlines, active-page state and 44px targets; the theme control exposes its pressed state.

Avatars retain the player's chosen palette in both themes. Existing venue photos and provider-hosted Google Maps iframe contents keep their own appearance; surrounding app surfaces follow the theme.

Validation: production Angular build, strict theme-test type checking, 3 theme tests and 14 existing frontend logic tests passed locally. Theme tests cover device defaults/changes, explicit overrides, persistence/reload, blocked/invalid storage, cross-tab reset, listener cleanup and the actual pre-bootstrap script. Browser visual, responsive and keyboard review remains manual: inspect header wrapping, both themes on Users/My Games/organizer forms, payment/strike overlays and sign-in, and follow the bell/cog shortcuts.
