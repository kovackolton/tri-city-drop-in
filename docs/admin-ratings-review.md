# Users, administrator ratings and account roles

Administrator Users combines the searchable, paginated user directory, optional administrator rating editor and role controls. There is no separate Player ratings navigation page. Self and administrator ratings are displayed side by side. Save the administrator rating per user, or choose Not rated to clear it; self-ratings remain independently managed by players.

Organizers see both labeled ratings in player search and selection, event player lists and team assignment lists. Auto-balance and Reshuffle & rebalance use the administrator rating when available, otherwise the self-rating. Players without either rating, and guests without their own profiles, use 3/5. Guests never inherit their host's ratings. Manual team assignments remain available after either balancing action. Existing assignments are not automatically recalculated when a rating changes. Ratings remain absent from public and shared player lists; players cannot edit administrator ratings through profile updates.

Each user card offers Player, Organizer and Administrator roles. Change role opens a confirmation showing the old and proposed roles. Administrator promotions explain the full permissions being granted. Self-demotion is allowed and explicitly explains that another administrator would be needed to restore access. The acting user's profile refreshes after a self-change, and the app leaves an administrator page when access is lost. Other recipients can refresh access from their in-app role-change notification. Server guards read current database roles on requests, so old UI state cannot retain permissions.

Only an administrator may update roles. The role update transaction locks actor and target consistently and rechecks authority, validates the exact role, records previous/new roles in the audit log and sends an in-app notification. Repeating an unchanged role has no side effects. Assigning Organizer or Administrator grants any pending organizer request and marks associated admin request notifications read. Player demotion preserves owned events and booking history; it removes organizer endpoint access rather than deleting data. The legacy direct-organizer endpoint and request grant/clear routes remain compatible.

Local schema migrations from this iteration add the nullable administrator rating with a database 1-5 constraint and allow account audit entries without an event. The merged-page/general-role follow-up needs no additional schema migration.

Validation: API compilation, production frontend build, 35 API unit tests, 44 isolated PostgreSQL scenarios and 14 frontend logic tests passed, plus strict frontend harness type checking. Coverage includes optional/invalid ratings, independent self-ratings, private projections, audit entries, all role transitions, unauthorized changes, self-demotion, repeated grants, request cleanup and combined scores in both balance paths. No external service calls were used. Browser visual/focus review remains manual.

During the prior schema generation, the running Windows API held the Prisma engine DLL and the engine-file rename reported EPERM. Generated metadata/types were updated and the same-version existing engine passed the PostgreSQL scenarios. Local migrations applied without stopping the development server.
